Filtering and aggregation of peak-picked and normalized MSI data further concentrate signal and reduce noise. Additionally, these steps reduce the number of features, and therefore the number of statistical comparisons. Fewer tests mean less stringent multiple hypothesis correction and greater experimental sensitivity. Unfortunately, feature clustering is computationally intensive and may require access to high-performance computing resources.

Feature clustering

Clustering of related features is an active field of research with many implementations. Choosing a clustering algorithm should be done based on what you want to cluster (related molecules, spatial analogs, isotopes, adducts, precursors, etc.) and the methods to cluster (spatial similarity, kendrick mass defect, intensity ratios, etc.). As such, we treat feature clustering as an interchangeable step that takes in MSIs and returns meaningful feature clusters to the experiment.

As of version 3.6, Cardinal does not offer feature clustering methods. In this work we tested DeepION to cluster isotopes and adducts (ACS Paper, Github), and mzClustering to cluster related spatial analogs (Bioinformatics Paper, Original Github, Github of install-ready version, made possible by Nihira Golasangi). At the time of publication, these methods were experimentally tested but lacked easy-to-install implementations. mzClustering has been updated by Nihira Golasangi to be install-ready from Github. DeepION may require more work to reconcile package conflicts, especially if using Apple M series chipsets. Both methods use spatial similarity to cluster features. mzClustering creates groups of similar features, while DeepION tests similarity of possible isotopes, as determined by mass differences.

Although powerful, we did not find the computational overhead of these methods to be feasible for most analyses. Additionally, neither is design for multi-sample datasets. We have instead opted to perform rudimentary clustering of C-13 isotopes using simpler methods, specifically by first identifying isotopic candidates with a known mass delta (with a mass error tolerance) then classifying candidates as isotopes by their ion image similarity. We will use pearson correlation of to assess spatial similarity and select the similary cutoff as the lowest correlation value yeilding minimal incorrect classification of random decoys pairs.

The helpers below live in IsotopeUtilities.R; each step is a small function so the process stays visible here. First, enumerate candidate pairs whose mass gap matches a C-13 spacing (k = 1, 2) within our mass tolerance. This uses no ion images, only m/z.

mse_corr <- mse
X    <- as.matrix(spectra(mse_corr))
mzv  <- mz(mse_corr)
runf <- as.factor(run(mse_corr))

candidates <- find_isotope_candidates(mzv, ppm = 20, iso_spacing = 1.00335, iso_orders = 1:2)

Score each candidate by the spatial similarity of its two ion images. We correlate within each run and aggregate with the median, so a pair must co-localize consistently across samples. Swap run_agg/pixel_mask here to change the correlation definition.

candidates$corr <- score_pairs(candidates, X, runf, run_agg = "median", pixel_mask = "all")

To pick a cutoff we need a null. Following MetaSpace’s target-decoy FDR, we re-pair each candidate anchor with random features at implausible mass offsets (>3 Da, so they cannot be isotopes), repeated 20 times, and score those the same way.

decoys <- make_decoy_pairs(candidates, mzv, n_rep = 20, min_mz_gap = 3, seed = 1)
decoys$corr <- score_pairs(decoys, X, runf, run_agg = "median", pixel_mask = "all")

The cutoff is the lowest correlation at which the estimated FDR (median decoy hits / candidate hits) falls to our target. Real candidates should pile up at high correlation while decoys stay low.

fdr    <- estimate_isotope_fdr(candidates$corr, decoys$corr, decoys$rep, target_fdr = 0.05)
cutoff <- fdr$cutoff

bind_rows(
  tibble(corr = candidates$corr, set = "candidate"),
  tibble(corr = decoys$corr,     set = "decoy")
) |>
  ggplot(aes(corr, y = after_stat(ncount), fill = set)) +
  geom_histogram(alpha = 0.5, position = "identity", bins = 40, na.rm = TRUE) +

  labs(x = "Pearson correlation", y = "scaled density", fill = NULL,
       title = sprintf("Isotope cutoff = %.2f (FDR = %.0f%%)", cutoff, 100 * 0.05))

Keep candidate pairs above the cutoff and resolve isotope groups as connected components (so an M+0/M+1/M+2 envelope becomes one group). Every feature gets a group_id; unmatched features are singletons.

iso_edges  <- candidates |> filter(is.finite(corr), corr > cutoff)

Feature aggregation

Isotopes are not expected to have the same abundance but are usually biologically identical. Unless experimental design requires the use of isotopes, such as experiments with C-13 labeling for quanitfication, isotopes can be aggregated without loosing any information. We will aggregate isotopes by selecting a representive ion and dropping the rest. For spatial analogs expected to be homogenous, other aggregation strategies like averaging may be more appropriate.

Aggregate feature clusters by selecting representative features with the highest mean intensity

We will aggregate features by selecting the feature with the highest mean intensity to serve as each isotope group’s representative feature.

Like during initial peak picking, we will apply a filter that will save us a lot of trouble later during statistical modeling. Highly sparse features create unstable estimates of mean abundance. The models detailed in this work assume normal distributions of residuals. Zero inflation will cause serious deviation from this assumption, yielding poor fit and invalid results. To keep things simple, we will drop features that are very sparse in the cartilage ROI. This represents a conservative modeling approach and will drastically reduce the number of features we continue analysis with. Alternate options include using models that are invariant to zero inflation.

Drop features that are present (non-zero and finite) in fewer than 25% of pixels in any run.
